# HOOZi 3.0 网页雷达

本仓库是 HOOZi 网页雷达的浏览器前端。当前版本接收 HOOZi 3.0
`web_radar.lua` 脚本生成的本地 WebSocket 状态数据流。

前端是由原生浏览器 ES Modules 和 Tailwind CSS v4 构成的静态站点，不使用
JavaScript bundler，也没有生产环境运行时依赖。

## HOOZi 3.0 迁移

旧版前端围绕 HOOZi 2.0 传输协议和单体 `app.js` 开发，依赖 2334 端口、
嵌套玩家坐标、数字地图 ID、基于昵称的本机玩家识别、旧版裁剪坐标系、
名册标记和派生长 UID。

HOOZi 3.0 版本改为严格遵循仓库中的 Lua 脚本：

- 自动 WebSocket 地址：本地或非 HTTPS 访问使用 `ws://127.0.0.1:9001/ws`，HTTPS 访问使用 `wss://<当前域名>/ws`
- 使用 `kind` 区分的完整 `state` 快照
- 原始 `game.world.map_name` 字符串，并使用已确认的地图别名，同时支持 `mp_lobby*` 和 `mp_rr_canyonlands_staging*` 图片展示模式
- 1000×1000 地图域中的扁平 `x`/`y` 坐标
- 稳定的玩家 `id` 和明确的 `self` 字段
- 生命、护盾、倒地/死亡状态、传奇、UID、等级、击杀、伤害、段位、
  队伍/小队、名册位标记和可选安全区
- 按已批准的 64 位无符号 XOR 掩码，从后端短 UID 派生仅用于显示的长 UID
- 可选的浏览器 `ping` 与 Lua `pong`
- 顶部栏提供横屏/竖屏、菜单栏显隐、玩家信息列表显隐，以及自由视角/固定跟随控制
- 横屏桌面布局保持表格列的固有宽度和横向滚动，并保证地图观察口的宽度始终不小于高度
- 地图绘制字段使用独立开关；玩家信息列表按当前 HOOZi 3.0 显示顺序提供字段列，原始字段仍保留用于导出但不再显示在控制项中
- 响应式观察口后方使用固定正方形雷达绘制表面，并支持 50%–300% 的按钮、滚轮和双指缩放
- 支持经过校验的当前 HOOZi `state` 玩家数据 JSON 导入与导出

浏览器渲染循环会在相邻 Lua 快照之间插值玩家位置和安全区几何数据。前端
不会伪造已经不受支持的 HOOZi 2.0 字段。

## 数据流

```text
HOOZi 3.0 运行时游戏数据
        ↓
web_radar.lua 快照与地图坐标转换
        ↓ 127.0.0.1:9001 上的 WebSocket JSON
src/protocol/hoozi3.js 验证和归一化
        ↓
src/state/store.js 快照状态与插值
        ↓
Canvas 雷达、玩家表格、焦点信息和控制项
```

`web_radar.lua` 只监听环回地址。如果通过独立 HClient 中继开放网页雷达，
请在“手动”模式中配置相应的 `ws` 或 `wss` 地址。中继鉴权不属于本仓库，
也不属于 Lua 协议。

完整消息和字段定义见
[`docs/protocol/hoozi3-web-radar-protocol.md`](docs/protocol/hoozi3-web-radar-protocol.md)。

## 雷达观察口与缩放

响应式地图面板只是观察口，不参与决定雷达内容的绘制比例。绘制表面始终保持宽高相等，
边长取初始观察口宽高中的较小值。因此在 100% 时，地图宽或高至少有一边刚好达到观察口
对应边界，完整正方形地图保持可见；观察口较长的方向允许留空。桌面端初始列宽布局稳定后，
绘制表面尺寸即被锁定；此后缩放浏览器窗口或切换玩家信息列表，只改变可见裁剪范围。

雷达缩放严格限制在 50%–300%。页面默认使用固定跟随并从 150% 开始；选择自由视角时会
重置为居中的 100%，重新选择固定跟随时会重置为 150% 并把选中玩家置于中心。右下角的
减号、倍率、加号控件、鼠标滚轮和移动端双指手势共用同一套限幅计算。自由视角会保持手势
锚点下的地图位置不漂移。

被选中的关注玩家会显示贯穿地图的白色十字定位线，并在玩家圆点外侧增加白色圆环。本机玩家
圆点的红色边框与是否被选中相互独立，仍然保留。

地图 `<img>` 初始不设置 `src`，并在未连接、尝试回退资源或资源缺失时保持隐藏。只有某个
配置的静态资源源成功加载后才显示，因此不会再出现裂图占位图标。

视口宽高比不小于 `1.12` 时会自动使用横屏布局，不大于 `0.893` 时会自动使用竖屏布局。
两个阈值之间的近方形区间保留顶部按钮中的用户选择。在横屏布局中，玩家列表会朝当前
可见内容的固有宽度扩张，但不会超过页面内容宽度的 25%。地图会优先取得足以满足
`宽度 >= 高度` 的空间。竖屏布局会从上到下排列地图、玩家信息列表和菜单栏；除非地图
是主体中唯一可见面板，否则地图绘制区域使用 `1:1.12` 的宽高比。顶部按钮在横屏和竖屏下
都能独立控制菜单栏和玩家信息列表显隐。竖屏玩家列表会展开显示全部行，只让表格字段列
在内部横向滚动。窗口缩放、布局切换、表格字段变化、快照内容变化以及菜单/玩家列表显隐
变化后，都会重新执行同一套分配规则。

玩家信息列表工具栏会把最新的完整 `state` JSON 导出为当前玩家信息。导出文件中的对象键
按字典顺序排列并使用 4 个空格逐级缩进；玩家按队伍编号升序排列，同队玩家再按昵称排序。
左侧的导入按钮
只接受 `.json` 文件，并在应用前使用同一套 HOOZi 3.0 协议校验器进行验证。无效 JSON、
非 `state` 消息或格式错误的玩家数组不会修改当前雷达状态。有效导入会进入离线预览，
停止当前连接并取消尚未执行的首次连接；只有用户明确点击连接或重连后才恢复连接。导入的
测试数据不会改变实时 WebSocket 的时间戳顺序，下一条有效实时快照可以正常接管。

## 本地运行

浏览器原生 ES Modules 必须通过 HTTP 提供。直接双击 `index.html` 会生成
`file://` 地址，浏览器会阻止它加载模块。

请在仓库根目录使用内置服务器：

```powershell
npm start
```

该命令会在 `http://127.0.0.1:8080/` 提供项目，并使用默认浏览器打开页面。
如果只需要启动服务器而不打开浏览器，请执行 `npm run serve`。

也可以使用其他静态 HTTP 服务器，例如：

```powershell
python -m http.server 8080
```

打开 `http://127.0.0.1:8080/`，并确认 HOOZi 3.0 已加载
`web_radar.lua` 且网页雷达 server 已启用。页面触发 `load` 事件后，本机自动模式只会尝试
连接 `ws://127.0.0.1:9001/ws` 一次。仓库中的 Lua server 监听本机端口，并不会按路径定义
另一套负载协议。连接失败或后续断开不会自动重试；需要再次连接时请使用连接或重连按钮。

如果页面本身使用 HTTPS，自动模式会使用 `wss://<当前域名>/ws`，不显式指定端口。手动模式
仍可填写完整 `ws://` 或 `wss://` 地址，用于局域网后端设备或自定义中继；手动地址为空或
填写 `auto` 时会回退到同一套自动目标。

## 安装、开发样式与生产构建

安装锁定的开发依赖：

```powershell
npm install
```

修改 `index.html` 或 JavaScript 中的 Tailwind utility class 后重新生成样式：

```powershell
npx @tailwindcss/cli -i ./input.css -o ./styles.css
```

开发模式仍不打包：`npm start` 直接提供原生 ES Modules。发布公网前，使用以下命令生成
完整的混淆生产站点：

```powershell
npm run build
```

该命令会重新生成压缩后的 Tailwind CSS，使用 esbuild 将应用打包为单一、压缩的浏览器
IIFE，再应用 `obfuscator.config.mjs` 中的平衡型混淆配置，最终把可部署的 `index.html`、
`styles.css`、`assets/app.<内容哈希>.js`、`static/` 和 `res/` 写入 `dist/`。构建不会生成
source map。可以使用 `npm run preview` 本地验证生产包。

默认配置使用不依赖 `eval` 的浏览器目标、RC4 字符串数组、适度控制流平坦化、低比例死代码
和自防御输出。属性/全局名称重命名以及会冻结开发者工具的反调试功能保持关闭，因为这些选项
会带来不成比例的兼容性和性能风险。构建完成后不要再次格式化或压缩生成的
`dist/assets/app.*.js`，自防御代码会有意检测后续改写。HTTP gzip/Brotli 传输压缩是安全的，
但应关闭 CDN 针对该资源的 JavaScript 自动压缩、脚本改写和注入功能。内容哈希允许配置长期
不可变缓存，同时避免用户加载旧代码。

如需提高直接复制到其他站点运行的难度，可以在构建时设置一个或多个域名（前导点包含所有
子域名）：

```powershell
$env:HOOZI_DOMAIN_LOCK='.example.com,www.example.net'
npm run build
```

只有在最终生产域名确定后才应启用；未列入的预览或测试域名将无法运行。混淆只能提高复制和
逆向成本，浏览器收到的代码原则上仍可恢复，因此绝不能在前端保存私钥、中继密钥或信任判断。

## 地图与静态资源

静态图片资源有两个来源：`https://img.hoozi.net/static/` 和 `static/`。

本地或非 HTTPS 访问会先尝试 `static/`，失败后再回退到 R2；HTTPS 访问会先尝试 R2，失败后
再回退到 `static/`。图片元素使用 `referrerPolicy="origin"`，让跨域 R2 图片请求按浏览器
支持的方式携带当前页面 origin 作为 referrer。

已知 BR 地图只读取 `mp_rr_` 后第一个下划线分隔标识，忽略 `_mu1`、`_mu2` 等后续变体。
确认的资源映射为：`canyonlands` → `1.png`、`desertlands` → `2.png`、
`olympus` → `3.png`、`divided` → `4.png`、`tropic` → `5.png`、
`nemesis` → `6.png`。`mp_rr_canyonlands_staging*` 会先于普通 `canyonlands`
规则匹配，并使用 `mp_range.png`。`mp_lobby` 开头的原始地图名使用 `mp_lobby.png`。
大厅和射击场都会以居中、保持比例、不超过地图绘制区域宽高的方式显示，不再按玩家坐标绘制玩家或安全区。未知原始地图名仍使用
精确的 `<map>.png` 查找。

传奇和段位图标 key 会保留在归一化状态及导出的快照中。非空 key 会在玩家信息列表的
“传奇”和“段位”合并列中按与地图图片相同的优先级加载。传奇图标会从
`https://img.hoozi.net/icon_legends/` 或本地 `./res/icon_legends/` 解析；段位图标会从
`https://img.hoozi.net/icon_rank/` 或本地 `./res/icon_rank/` 解析。例如 `icon_rank/rookie1`
会在选中的段位图标 base URL 下使用 `rookie1.png`。这些 PNG 会按透明背景直接显示。
`rank_color` 仅保留在状态和导出数据中，不再作为可见表格字段。

`roster` 会按四个位标记显示：好友 `8`、作弊 `4`、权限/Pro `1`、名人 `2`。玩家信息列表中
标记会显示在“昵称”列里，位于玩家昵称左侧，并使用对应颜色；繁体中文和英文会显示各自
本地化的半角中括号标签。玩家信息列表的昵称在有标记时使用最左侧标记颜色；地图绘制里
仅标记序列使用最左侧标记颜色，昵称和其他标签文本仍使用玩家圆点颜色。`legend` 的
`pilot_medium_empty` 和 `rank` 的 `None` 会显示为空。
护盾品质、护盾和血量合并为一个“护盾 & 血量”条形列；当 `max_shield` 为 `0` 时，只省略护盾条。

## 开发规则

- 修改协议或渲染语义前，先阅读根目录 `AGENTS.md` 和要求的参考文件。
- `references/hapex3-lua-script-factory/` 必须保持只读。
- 以 `web_radar.lua` 为首要事实来源，不要从旧前端推断 HOOZi 3.0 语义。
- 协议解析、状态、Canvas 渲染、DOM 控制和资源回退应保持在现有模块中。
- 用户可见文本需要同时更新简体中文、繁体中文和英文。
- 未经明确批准，不要增加 bundler 或生产依赖。
- Tailwind class 发生变化时必须重新生成 `styles.css`。

## 已知协议限制

当前 Lua 脚本没有发送战利品或投掷物数组，因此前端无法渲染这些实体。
参考资料没有完整定义 yaw 朝向，因此前端只保留该值，不绘制方向箭头；完整的不确定项列表见协议文档。
